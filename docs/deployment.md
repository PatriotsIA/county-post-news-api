# Deployment

This service deploys from GitHub through AWS CodePipeline and CodeBuild. It does not use GitHub Actions.

The important detail: this is a TypeScript/SAM app, so CloudFormation cannot deploy the raw `template.yaml` directly. The pipeline must run a build/package step first. CodeBuild turns `template.yaml` into `packaged.yaml`, where Lambda `CodeUri` points to S3.

## Deployment Shape

Use this pipeline shape:

```text
GitHub Source -> CodeBuild -> CloudFormation Deploy
```

The repository files involved are:

- `template.yaml`: SAM template for the Lambda Function URL.
- `buildspec.yml`: CodeBuild commands that install, test, build, run `sam build`, and package the SAM app.
- `buildspec.atlas.yml`: commands used later by the separately scheduled atlas ingestion project.
- `packaged.yaml`: generated by CodeBuild and used by the CloudFormation deploy action.

The API deployment does not ingest federal datasets. CloudFormation provisions a second CodeBuild project that EventBridge starts on its own schedule after the stack is deployed.

## Before You Start

Use one AWS region consistently for:

- CodePipeline
- CodeBuild
- CodeConnections
- S3 artifact bucket
- CloudFormation stack
- Lambda function

Recommended region: choose the region where CodeBuild quota is available. If one region reports `AccountLimitExceededException` for CodeBuild, use another region or request a CodeBuild quota increase.

Make sure the GitHub repo has this project pushed to the branch you plan to deploy, usually `main`.

## Step 1: Create The Pipeline Source And Build

In AWS Console:

1. Open `Developer Tools > CodePipeline > Pipelines`.
2. Choose `Create pipeline`.
3. On `Choose creation option`, select:
   - Category: `Continuous integration`
   - Template: `CI Build NodeJS`
4. Choose your GitHub source through CodeConnections:
   - Repository: `ErikBurdett/county-post-news-api`
   - Branch: `main`
5. Configure the Node.js build project.
6. Make sure the build uses the repository `buildspec.yml`.

The buildspec runs:

```bash
npm ci
npm run typecheck
npm test
npm run build
sam build
sam package --template-file .aws-sam/build/template.yaml --s3-bucket "$ARTIFACT_BUCKET" --output-template-file packaged.yaml
```

## Step 2: Create Or Choose An Artifact Bucket

CodeBuild needs an S3 bucket for packaged SAM artifacts.

Create or choose a bucket in the same region as the pipeline. Example name:

```text
county-news-api-artifacts-<account-id>-<region>
```

In the CodeBuild project environment variables, add:

```text
ARTIFACT_BUCKET=<your-artifact-bucket-name>
```

The CodeBuild service role must be able to write to this bucket.

## Step 3: Confirm Build Output

The CodeBuild action must output:

```text
packaged.yaml
```

The repo `buildspec.yml` already declares this artifact:

```yaml
artifacts:
  files:
    - packaged.yaml
```

If CodeBuild succeeds, the build artifact should contain `packaged.yaml`.

## Step 4: Add CloudFormation Deploy Stage

After the CI pipeline exists, edit it and add a deploy stage:

1. Open the pipeline.
2. Choose `Edit`.
3. Add a stage after the CodeBuild stage.
4. Add an action:
   - Action provider: `CloudFormation`
   - Action mode: `Create or update a stack`
   - Input artifact: the CodeBuild output artifact
   - Template file: `packaged.yaml`
   - Stack name: `county-news-api`
   - Capabilities: `CAPABILITY_IAM` and `CAPABILITY_AUTO_EXPAND`
   - Parameter overrides: set `UsdaMarsApiKey` to the USDA MARS key, `FredApiKey` to the FRED key, and `StripeSecretKey` to the Stripe secret key. Set `StripeCheckoutSuccessUrl` and `StripeCheckoutCancelUrl` to the deployed frontend payment URLs. Remove any legacy `MetalsApiKey` override: the metals ticker now uses the no-key Minted Metal endpoint configured in `template.yaml`.
   - Atlas overrides: set `CensusApiKey` to a free Census API key, select the released ACS year with `AtlasCensusYear`, and confirm `AtlasSourceLocation`, `AtlasSourceVersion`, and `AtlasIngestionSchedule`.

Do not point this deploy action at raw `template.yaml`. Raw `template.yaml` has `CodeUri: .`, which causes this error:

```text
CodeUri is not a valid S3 Uri
```

Only deploy `packaged.yaml`.

The stack also provisions two private encrypted buckets. `AdvertisingCreativeBucket` accepts only short-lived presigned browser uploads. The versioned `AtlasDataBucket` blocks public access, is retained on stack deletion, and can be read by the API Lambda only. Do not make either bucket public.

County weather uses the public, no-key `https://api.weather.gov` service, the public U.S. Drought Monitor county-statistics service, and the public NASA POWER Daily API. These outbound HTTPS requests add no IAM policy or secret parameter. The SAM environment supplies an identifying `NWS_USER_AGENT`; update its domain/contact if the application identity changes. Defaults are 86,400 seconds for point mappings, 600 seconds for forecasts/observations, 180 seconds for alerts and public weather responses, 21,600 seconds for weekly drought conditions, 86,400 seconds for 14-day NASA precipitation history, and 5,000 ms per request. See the official [NWS API documentation](https://www.weather.gov/documentation/services-web-api), [NWS alerts documentation](https://www.weather.gov/documentation/services-web-alerts), [U.S. Drought Monitor web-service documentation](https://www.droughtmonitor.unl.edu/DmData/DataDownload/WebServiceInfo.aspx), and [NASA POWER Daily API documentation](https://power.larc.nasa.gov/docs/services/api/temporal/daily/).

## Atlas ingestion setup

The stack creates `${stack-name}-atlas-ingestion`, which clones `AtlasSourceLocation` and runs `buildspec.atlas.yml` independently of the deployment pipeline. The default public repository can be cloned directly. If the source becomes private, configure a CodeBuild GitHub source credential or CodeConnections authorization in the account before enabling the schedule.

The ingestion project receives only:

- list/location and object read/write permissions for `AtlasDataBucket` (no delete);
- write access to its dedicated CloudWatch Logs group;
- permission to publish the `CountyPost/Atlas` health metric.

EventBridge receives only `codebuild:StartBuild` for that project. The API Lambda receives read-only atlas bucket access.

After the first stack deployment:

1. Open the `AtlasIngestionProjectName` stack output and start one manual build.
2. Confirm the build validates the ACS county count and logs `atlas.publish.succeeded`.
3. In `AtlasDataBucketName`, confirm a version prefix exists and `manifest/current.json` points to it.
4. Call `/v1/counties/arkansas/polk/atlas` and confirm `meta.version` matches the manifest.
5. Attach SNS or another notification action to `AtlasBuildFailureAlarm`, `AtlasScheduleFailureAlarm`, and `AtlasStaleDataAlarm`. The template creates alarms but cannot choose an account-specific recipient.

`CensusApiKey` is free but required for live Census Data API queries as of May 2026. Offline fixture ingestion does not need it. `FRED_API_KEY` is used by the API's development fallback and existing economic endpoint; FRED scheduled snapshot ingestion is not yet enabled.

To verify ingestion without network or AWS:

```bash
npm run atlas:ingest -- --fixture tests/fixtures/atlas/census-acs.json --output .atlas-output
```

The publisher uploads every immutable `versions/<version>/...` object before replacing `manifest/current.json`, so a failed refresh leaves the prior snapshot active.

## Step 5: Confirm CORS Origins

The deployed API should only allow requests from frontend origins that should call it. The current production allowlist is:

```text
https://main.d2z6lt4e5q50in.amplifyapp.com,https://advertiser-preview.d2z6lt4e5q50in.amplifyapp.com,https://thecountypost.com,https://www.thecountypost.com
```

These origins are configured with the `template.yaml` `CORS_ORIGINS` environment variable. The API response code echoes one matching origin from that allowlist.

Do not also configure Lambda Function URL CORS for this API. Adding CORS at both the Function URL layer and in the API response can produce duplicate `Access-Control-Allow-Origin` headers, which browsers reject.

Do not include trailing slashes in CORS origins. Browser `Origin` headers look like `https://thecountypost.com`, not `https://thecountypost.com/`.

## County coverage rollout

The SAM template ships the bounded county expansion settings. For the first production verification, deploy with `COUNTY_MARKET_TIER_ENABLED=false` if you need to isolate the strict-primary and nearby-county behavior. Then enable it after inspecting:

- county response `meta.sourcesUsed` for `county:primary`, `county:market`, and `county:fallback-nearby`;
- CloudWatch `feed.sparse_county` log records for primary, market, nearby, and final counts;
- pilot responses for ambiguous names such as `/v1/feeds/counties/arkansas/polk/general` and `/v1/feeds/counties/florida/polk/general`.

Keep `COUNTY_LOCAL_SOURCE_SEARCH_ENABLED=true` and `COUNTY_PUBLISHER_BALANCE_ENABLED=true`. Leave the 25-story `COUNTY_SINGLE_PUBLISHER_MAX`, 25-story `COUNTY_OTHER_SOURCES_TARGET`, query limits, and `COUNTY_NEARBY_LIMIT` at their template defaults unless measured coverage and latency justify changing them. These settings are deployed with the Lambda template and require no separate AWS resource.

## Step 6: CloudFormation Permissions

For the first deployment, the CloudFormation deploy role needs permission to create/update:

- Lambda function
- Lambda Function URL
- IAM execution role
- CloudWatch Logs
- S3 deployment artifacts
- the private versioned atlas S3 bucket and bucket policy
- the atlas CodeBuild project and service role
- the EventBridge schedule and start-build role
- CloudWatch log group, metrics, and alarms
- CloudFormation stack resources

If the AWS console asks for `CloudFormationResourcePermissions`, this broad first-deploy policy works:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "CloudFormationDeployCountyNewsApi",
      "Effect": "Allow",
      "Action": [
        "cloudformation:*",
        "lambda:*",
        "iam:*",
        "logs:*",
        "s3:*",
        "codebuild:*",
        "events:*",
        "cloudwatch:*"
      ],
      "Resource": "*"
    }
  ]
}
```

This should be tightened after the first successful deployment.

For a constrained deploy role, include `iam:PassRole` for the generated atlas CodeBuild role (passed to `codebuild.amazonaws.com`) and EventBridge start-build role (passed to `events.amazonaws.com`), plus create/update/delete and tagging actions for the listed S3, CodeBuild, Events, Logs, and CloudWatch resources. The runtime ingestion role itself does not need `iam:PassRole`.

## Step 7: Run The Pipeline

Run or release a new pipeline change.

Expected result:

```text
Source: success
Build: success
Deploy: success
```

If the build fails, open the CodeBuild logs first.

If deploy fails, open:

```text
CloudFormation > Stacks > county-news-api > Events
```

Look for the first red `CREATE_FAILED` or `UPDATE_FAILED` event. Later rollback messages usually hide the real cause.

## Step 8: Find The API URL

After the CloudFormation deploy succeeds:

1. Open `CloudFormation`.
2. Open the `county-news-api` stack.
3. Go to `Outputs`.
4. Copy `NewsApiUrl`.

The same Outputs tab also contains `AtlasDataBucketName`, `AtlasIngestionProjectName`, and `AtlasIngestionScheduleName`.

The output comes from `template.yaml`:

```yaml
Outputs:
  NewsApiUrl:
    Description: Public Lambda Function URL for the news API.
    Value: !GetAtt NewsApiFunctionUrl.FunctionUrl
```

Test it:

```bash
curl "https://<function-url-id>.lambda-url.<region>.on.aws/health"
curl "https://<function-url-id>.lambda-url.<region>.on.aws/v1/pages/counties/arkansas/polk?limit=48"
curl "https://<function-url-id>.lambda-url.<region>.on.aws/v1/counties/arkansas/polk/weather"
curl "https://<function-url-id>.lambda-url.<region>.on.aws/v1/counties/arkansas/polk/atlas"
```

## Step 9: Configure The Frontend

Set this environment variable in the frontend deployment:

```text
VITE_NEWS_API_URL=https://<function-url-id>.lambda-url.<region>.on.aws/
```

Then redeploy the frontend.

The frontend should use page endpoints for initial loads:

- `/v1/pages/national`
- `/v1/pages/states/:stateSlug`
- `/v1/pages/counties/:stateSlug/:countySlug`

## Troubleshooting

### CodeBuild quota is zero

Error:

```text
Cannot have more than 0 builds in queue for the account
```

Fix:

- Use another region with CodeBuild quota available, or
- Request a CodeBuild quota increase in `Service Quotas`.

### CloudFormation says `CodeUri is not a valid S3 Uri`

Cause:

- CloudFormation is deploying raw `template.yaml`.

Fix:

- Add/run CodeBuild first.
- Deploy CodeBuild output `packaged.yaml`.

### Stack is `ROLLBACK_COMPLETE`

CloudFormation cannot update a stack in `ROLLBACK_COMPLETE`.

Fix:

- Delete the failed stack.
- Re-run the pipeline after fixing the cause.

### No API URL appears

Likely causes:

- Deploy stage did not run.
- Deploy stage failed.
- You are looking at the pipeline infrastructure stack instead of the API app stack.

Fix:

- Open the `county-news-api` application stack, not the `CodePipelineStarterTemplate...` stack.
- Check the `Outputs` tab for `NewsApiUrl`.
